## 1. Model Context Protocol (MCP): version, governance, what changed in 2026, which products are MCP clients, and MCP for agent-to-agent

### Takeaway
MCP is the one protocol every major assistant vendor ships as a client today (ChatGPT, Claude, Grok, Microsoft Copilot Studio and Microsoft 365 Copilot, Gemini Enterprise). The current specification is 2026-07-28, a breaking "stateless" rewrite, governed by individual maintainers under the Linux Foundation's Agentic AI Foundation. MCP is being used to expose whole agents as "tools", but it remains a tool-calling protocol: the assistant always calls out, and the pieces that would make it a true agent-to-agent protocol (long-running tasks, server-initiated messages, agent identity) are extensions or roadmap items.

### Cited Findings

#### Version and what changed
- The latest specification is **2026-07-28**, released on July 28, 2026 by Lead Maintainers David Soria Parra and Den Delimarsky. The previous revision was 2025-11-25. — [MCP blog, "The 2026-07-28 Specification", 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/); [MCP changelog 2026-07-28, retrieved 2026-11-23](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- The release turns MCP "from a bidirectional stateful protocol into a request/response stateless protocol": the `initialize` handshake and the `Mcp-Session-Id` header are removed, every request carries its protocol version and client capabilities, and any request can reach any server instance behind a load balancer. Servers must implement a new `server/discover` call that advertises versions, capabilities and identity. — [MCP blog, 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/); [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- It is a breaking release. The maintainers say there will be "some migration cost", especially for developers who relied on session identifiers. TypeScript, Python, Go and C# SDKs supported it on release day; Rust was in beta. — [MCP blog, 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- **Remote servers over HTTP:** Streamable HTTP is the remote transport. The older HTTP+SSE transport (deprecated since protocol version 2025-03-26) was formally reclassified as Deprecated. Requests must now carry `Mcp-Method` and `Mcp-Name` headers so gateways can route and meter without reading bodies. SSE stream resumability was removed. — [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- **Authorization (OAuth):** OAuth Dynamic Client Registration (DCR, RFC 7591) is deprecated in favour of Client ID Metadata Documents (CIMD), where the client's ID is a public URL pointing to its metadata. DCR "remains available for backwards compatibility". Clients must validate the `iss` parameter (RFC 9207) and must not reuse credentials across authorization servers. — [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- CIMD, URL-mode elicitation, experimental Tasks, OAuth client credentials (machine-to-machine) and Enterprise-Managed Authorization were introduced in the 2025-11-25 release. — [MCP blog, "One Year of MCP: November 2025 Spec Release", 2025-11-25](https://blog.modelcontextprotocol.io/posts/2025-11-25-first-mcp-anniversary/)
- **Enterprise-Managed Authorization (EMA)** became a stable extension on June 18, 2026. An organization provisions MCP server access through its identity provider; "The user is never redirected through a per-server consent screen." It embeds the Cross App Access protocol (Okta's implementation is called XAA) and uses an Identity Assertion JWT Authorization Grant (ID-JAG). Named support: Okta as identity provider; Claude, Claude Code and Cowork as clients; VS Code in preview; Asana, Atlassian, Canva, Figma, Granola, Linear and Supabase as servers. Microsoft is named as adopting the extension, but no Microsoft identity product is named as supported. — [MCP blog, "Enterprise-Managed Authorization", 2026-06-18](https://blog.modelcontextprotocol.io/posts/enterprise-managed-auth/)
- **Long-running / asynchronous tasks:** Tasks shipped as experimental in 2025-11-25 and were moved out of the core into an official extension (`io.modelcontextprotocol/tasks`) in 2026-07-28, redesigned around polling (`tasks/get`) plus `tasks/update`. — [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- **Elicitation (asking the user for input mid-call):** server-initiated requests (`elicitation/create`, `sampling/createMessage`, `roots/list`) were replaced by "Multi Round-Trip Requests": the server answers `input_required` and the client retries the call with the answers. — [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- **Deprecated features:** Roots, Sampling and Logging are deprecated; they "will keep working for at least twelve months". A formal deprecation policy sets a twelve-month minimum window. — [MCP blog, 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/)
- **UI extension (MCP Apps):** announced January 26, 2026 as "the first official MCP extension" and "ready for production". Tools return interactive UI that the host renders in a sandboxed iframe. It builds on MCP-UI and the OpenAI Apps SDK. Launch clients: Claude (web and desktop), Goose, VS Code Insiders, and ChatGPT from the week of the announcement. — [MCP blog, "MCP Apps", 2026-01-26](https://blog.modelcontextprotocol.io/posts/2026-01-26-mcp-apps/)
- In March 2026 Microsoft 365 Copilot added interactive UI widgets for declarative agents, built "by extending MCP server-based actions by using the OpenAI Apps SDK". — [Microsoft Learn, "What's New for Microsoft 365 Copilot Developers", ms.date 2026-11-13](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new)
- **Official registry:** launched in preview on September 8, 2025 and is still labelled "currently in preview. Breaking changes or data resets may occur before general availability." It is a metadata catalogue for *public* servers only, "backed by major trusted contributors to the MCP ecosystem such as Anthropic, GitHub, PulseMCP, and Microsoft", meant to be consumed by downstream marketplaces rather than directly by host apps. It does not scan server code for security. — [MCP docs, "The MCP Registry", retrieved 2026-11-23](https://modelcontextprotocol.io/registry/about); [MCP blog, registry preview, 2025-09-08, OLDER THAN 12 MONTHS](https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/)
- The registry had "close to two thousand entries" in November 2025. — [MCP blog, 2025-11-25](https://blog.modelcontextprotocol.io/posts/2025-11-25-first-mcp-anniversary/)
- **Roadmap (August 22, 2026):** agentic messaging primitives (server-initiated events through webhooks and channels so that clients do not have to poll, maturing Tasks into the specification), HTTP-native transport, agent identity (DPoP, Workload Identity Federation, ID-JAG, work with the IETF OAuth and WIMSE groups), progressive tool discovery, and a Server Card working group defining `.well-known` metadata. — [MCP blog, "The New MCP Roadmap", 2026-08-22](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)
- A November 11, 2026 post announces "A More Predictable Release Cycle for MCP" with a release manager for the next spec cycle; a November 10, 2026 post explores a file upload/download extension. — [MCP blog index, retrieved 2026-11-23](https://blog.modelcontextprotocol.io/tags/mcp/)

#### Governance
- Anthropic donated MCP on December 9, 2025 to the Agentic AI Foundation (AAIF), a "directed fund under the Linux Foundation", co-founded by Anthropic, Block and OpenAI with support from Google, Microsoft, AWS, Cloudflare and Bloomberg. The AAIF Governing Board decides budget, membership and new projects; individual projects such as MCP keep full autonomy over their technical direction and daily operations. MCP's own governance model did not change. — [MCP blog, "MCP joins the Agentic AI Foundation", 2025-12-09](https://blog.modelcontextprotocol.io/posts/2025-12-09-mcp-joins-agentic-ai-foundation/)
- Legally the project is "Model Context Protocol a Series of LF Projects, LLC". Technical authority is hierarchical: Lead Maintainers hold final decision authority ("BDFL"), Core Maintainers steer the specification, Maintainers run working groups and SDKs. Seats belong to individuals, not companies: "there are no seats reserved for specific companies". Changes go through Specification Enhancement Proposals (SEPs). Lead Maintainers: David Soria Parra, Den Delimarsky. Core Maintainers: Peter Alexander, Caitie McCaffrey, Kurtis Van Gent, Clare Liguori, Paul Carleton, Nick Cooper. — [MCP docs, "Governance and Stewardship", retrieved 2026-11-23](https://modelcontextprotocol.io/community/governance)
- Den Delimarsky (Anthropic, previously Microsoft) became a Lead Maintainer and Clare Liguori (Amazon Web Services) joined the Core Maintainers in April 2026. — [MCP blog, "Expanding the MCP Maintainer Team", 2026-04-08](https://blog.modelcontextprotocol.io/posts/2026-04-08-maintainer-update/)
- AAIF's Platinum members are Amazon Web Services, Anthropic, Block, Bloomberg, Cloudflare, Google, Microsoft and OpenAI. — [Linux Foundation press release on AAIF formation, 2025-12-09 (search snippet, page not opened)](https://www.linuxfoundation.org/press/linux-foundation-announces-the-formation-of-the-agentic-ai-foundation)
- AAIF reported 305 member organizations on October 22, 2026. — [AAIF, "Agentic AI Foundation surpasses 300 members", 2026-10-22](https://aaif.io/news/agentic-ai-foundation-surpasses-300-members)

#### Which products are MCP clients today, and on which plans
- **OpenAI / ChatGPT.** Custom MCP servers are added on ChatGPT web as "apps"/"plugins". "Full MCP is only available to Business and Enterprise/Edu users, currently." Pro can connect custom MCP servers with read/fetch permissions. Free, Go and Plus are not mentioned on the page. Custom MCP servers cannot be connected on mobile. In deep research, custom apps are limited to read/fetch. On Business only admins/owners publish; Enterprise/Edu admins use role-based access and can switch individual actions on or off. Published workspace snapshots are "frozen" until an admin publishes an update. — [OpenAI Help Center, "Developer mode and MCP apps in ChatGPT", page shows "Updated: 27 days ago" on 2026-11-23](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)

Tools without the `readOnlyHint` annotation are treated as write actions and need confirmation by default. Server instructions beyond the first 512 characters may not be relied on. — [OpenAI developer docs, "ChatGPT Developer mode", retrieved 2026-11-23](https://developers.openai.com/api/docs/guides/developer-mode.md)

### Inferences
- "Claude's published identity" and "automatic registration" in Anthropic's help page most likely correspond to CIMD and DCR respectively; the page does not use those terms.
- Because the 2026-07-28 release deprecates Sampling (the feature that let a server borrow the client's model) and replaces server-initiated requests with client retries, MCP in late 2026 is more firmly "the assistant calls, the server answers" than it was a year earlier. Anything that needs the server to start the conversation waits on roadmap items (webhooks, channels).
- The limits of "agent as MCP server" follow from the protocol's shape: the calling assistant sees a tool with a name and description, not a peer with a published skills card; there is no standard lifecycle (pause, resume, cancel, hand back for input) outside the optional Tasks extension; and the result is one answer, not a negotiated multi-turn exchange.
- Plan access is uneven even where MCP is supported: write actions in ChatGPT need Business/Enterprise/Edu; Microsoft and Google put custom MCP behind administrators; only Claude and Grok let an individual add a custom server on consumer plans.

### Gaps
- Whether ChatGPT Plus (not Pro) users can connect custom MCP servers in November 2026 is unclear. OpenAI's help page names only Pro, Business and Enterprise/Edu; third-party guides claim Plus has read-only access (search snippet, not verified).
- Whether end users of the consumer Gemini app can paste an arbitrary custom MCP server URL is unconfirmed. Secondary sources (TechRepublic, Zapier, via search snippets) say "Gemini Spark" allows it; Google's developer page describes only a developer-registered, reviewed route.
- The official MCP Registry has no announced general-availability date; I found no 2026 statement beyond the "preview" label.
- Which products have already moved to the 2026-07-28 specification is not documented by the vendors I checked.
- Exact date of Copilot Studio's MCP general availability was not captured from the primary page.
- OpenAI's API-side MCP support (Responses API) was not re-verified in this session.

## 2. Agent2Agent (A2A): version, governance, core concepts, and who supports it in production

### Takeaway
A2A reached its first stable version (1.0) in March 2026 and moved into the Agentic AI Foundation in August 2026, alongside MCP. It is supported by enterprise platforms (Microsoft Foundry and Copilot Studio, Google, AWS, Salesforce, SAP, ServiceNow) but not by the three assistant makers the reader cares most about: OpenAI, Anthropic and xAI have no native A2A support in their products. Microsoft's support is real but layered: generally available for calling out to A2A agents, preview for exposing its own agents, and admin-gated in Microsoft 365 Copilot.

### Cited Findings

#### Version and governance
- A2A v1.0.0 was released on March 12, 2026 with many breaking changes; v1.0.1 (May 28, 2026) is a bug-fix release and the latest shown on the releases page. The previous line was v0.3.0 (July 30, 2025). — [A2A GitHub releases, retrieved 2026-11-23](https://github.com/a2aproject/A2A/releases)
- The Linux Foundation calls v1.0 the first stable specification. — [Linux Foundation press release, 2026-04-09](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
- Google created A2A and donated it to the Linux Foundation on June 23, 2025. — [Google Open Source Blog, "A year of open collaboration", April 2026 (search snippet, page not opened)](https://opensource.googleblog.com/2026/04/a-year-of-open-collaboration-celebrating-the-anniversary-of-a2a.html)
- On August 17, 2026 A2A joined the Agentic AI Foundation as a hosted project. AAIF's hosted projects at that date: AGENTS.md, goose, MCP, agentgateway and A2A. — [AAIF blog, "A2A joins AAIF's open agentic stack", 2026-08-17](https://aaif.io/blog/a2a-joins-aaif)
- Under AAIF's model, projects keep their own maintainers and technical direction, while the foundation provides neutral governance. — [Diginomica, 2026-09-10](https://diginomica.com/node/31091)
- A2A's Technical Steering Committee has representatives from Google, Microsoft, AWS, Cisco, Salesforce, ServiceNow, SAP and IBM. — [LF AI & Data, "ACP joins forces with A2A", 2025-08-29, updated 2025-09-04, OLDER THAN 12 MONTHS](https://lfaidata.foundation/?p=7689)

#### Core concepts (v1.0)
- **Agent Card:** a JSON description of an agent published at the well-known address `/.well-known/agent-card.json`, listing its interfaces (URL, protocol binding, protocol version), skills, and security requirements. Cards can be cryptographically signed (JWS). — [A2A project, "What's new in v1.0", retrieved 2026-11-23](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- **Three equivalent bindings:** JSON-RPC, gRPC and HTTP+JSON (REST). Clients send an `A2A-Version` header; one agent can expose several protocol versions at once. — [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- **Messages and parts:** a message has a role (`ROLE_USER` or `ROLE_AGENT`) and parts carrying text, raw bytes, a URL or structured data. — [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- **Tasks and task states:** `SUBMITTED`, `WORKING`, `COMPLETED`, `FAILED`, `CANCELED`, `REJECTED`, `INPUT_REQUIRED`, `AUTH_REQUIRED`. Operations include `SendMessage`, `SendStreamingMessage`, `GetTask`, `ListTasks`, `CancelTask` and `SubscribeToTask`. — [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- **Artifacts:** the outputs a task produces; streaming sends `statusUpdate` and `artifactUpdate` events. — [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- **Push notifications:** the client registers a callback configuration per task (`CreateTaskPushNotificationConfig` and related operations) so it is notified without holding a connection open. — [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- **Security in 1.0:** implicit and password OAuth flows removed; device code flow and PKCE added; mutual TLS can be declared; a `tenant` field supports multi-tenancy. — [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)

## 3. Other efforts and their current status

### Takeaway
Most rival agent-to-agent protocols have merged into A2A or retreated to niche roles; what is alive around MCP and A2A are complements: user-interface protocols (AG-UI, MCP Apps, A2UI), instruction formats (AGENTS.md, Agent Skills), identity work (OAuth profiles, IETF WIMSE, vendor agent IDs) and registries. Identity and cross-organization discovery remain unfinished.

### Cited Findings

#### Protocols

## 4. How MCP and A2A relate in practice, and whether the ecosystem is consolidating

### Takeaway
Officially they are complementary layers (MCP connects an agent to tools and data; A2A connects agents to each other) and since August 2026 they share one neutral home, the Agentic AI Foundation. In practice the boundary is blurring from the MCP side, and the market has consolidated around MCP as the universal layer, with A2A as an enterprise-platform layer that the main model vendors have not adopted.

### Cited Findings
- AAIF places the two at different layers: MCP for agent-to-tool connectivity, A2A for agent-to-agent interoperability. It announces no joint working group, shared registry or formal convergence effort. — [AAIF blog, 2026-08-17](https://aaif.io/blog/a2a-joins-aaif)
- The Linux Foundation describes A2A as complementary to MCP, not a replacement for it. — [Linux Foundation press release, 2026-04-09](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
- Microsoft's guidance is a per-need table: "Connect to APIs or basic HTTP services → Custom connectors / HTTP tools"; "Use MCP tools or resources → MCP servers"; agents already implementing the protocol → A2A. "You can combine multiple integration models within the same Copilot Studio agent." — [Microsoft Learn, ms.date 2026-08-26](https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-agent-agent-to-agent)
- AAIF's executive director frames the difference as control: with MCP the agent uses your tools; with A2A, "They are not both my agents, so I don't have the complete control." — [Diginomica, 2026-09-10](https://diginomica.com/node/31091)
- Consolidation events: IBM's ACP merged into A2A (August 2025); MCP entered AAIF (December 2025); A2A v1.0 (March 2026); A2A entered AAIF as its fifth hosted project (August 2026); Agent Skills entered AAIF (October 2026). — [LF AI & Data, 2025-08-29](https://lfaidata.foundation/?p=7689); [MCP blog, 2025-12-09](https://blog.modelcontextprotocol.io/posts/2025-12-09-mcp-joins-agentic-ai-foundation/); [AAIF blog, 2026-08-17](https://aaif.io/blog/a2a-joins-aaif); [AAIF blog, 2026-10-22](https://aaif.io/blog/agent-skills-sharing-team-expertise-across-ai-agents)
- Overlap from the MCP side: MCP's roadmap adds "agentic messaging primitives", matured Tasks and agent identity. — [MCP blog, 2026-08-22](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)
- Platforms increasingly offer both doors to the same agent: Copilot Studio's MCP and A2A channels share "the same connection model"; Work IQ is offered as A2A, MCP and REST; Foundry can wrap an A2A tool behind "an MCP-compatible endpoint". — [Microsoft Learn, ms.date 2026-09-30](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent); [Microsoft Community Hub, 2026-04-30](https://techcommunity.microsoft.com/blog/copilot-studio-blog/work-iq-api-public-preview-build-copilot-powered-agents-with-a2a/4516286); [Microsoft Learn, ms.date 2026-10-28](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/agent-to-agent)
- Practitioner view: "MCP is how an agent uses a tool. A2A is how an agent works with another agent"; "A2A did not replace MCP, and it was never going to"; the article adds that MCP reached mass adoption faster, largely because it is easier to start with. — [Credal, 2026-03-06, updated November 2026](https://credal.ai/blog/what-happened-to-a2a-protocol)
- Practitioner advice: start with MCP and add A2A only when ownership or interoperability constraints demand it; "Do not adopt A2A for vibes." — [Rost Glukhov, "Google A2A Protocol in 2026: Adoption, Hype, and Reality", 2026 (undated)](https://glukhov.org/ai-systems/comparisons/a2a-protocol-2026-adoption/)

### Inferences
- Consolidation is real at the governance level (one foundation, overlapping Platinum members and steering companies) and at the vocabulary level (everyone says "MCP for tools, A2A for agents"). It is not yet real at the product level: the assistant makers ship MCP only, the enterprise platforms ship both.
- The two protocols have different governance styles inside the same foundation: MCP is steered by named individuals with a strong Anthropic presence among lead maintainers; A2A by a committee of eight companies that, as last listed in 2025, does not include OpenAI or Anthropic. This helps explain the uneven product support.
- If MCP's Tasks and server-initiated messaging mature, the simplest cross-vendor "agent-to-agent" pattern may remain "expose the agent as an MCP server", with A2A reserved for cases where two organizations' agents must negotiate as peers.

### Gaps
- No public statement from AAIF, the MCP maintainers or the A2A steering committee about merging or formally aligning the two specifications was found.
- No neutral, quantitative comparison of MCP versus A2A usage (for example share of deployments) was found; available numbers are self-reported by each project.

## 5. Evidence of real use, and what critics and practitioners say

### Takeaway
What is happening in production at scale is tool-calling through MCP and plain APIs. Verified, named examples of agents from different vendors conversing over A2A are few and concentrated in Asian consumer ecosystems; no detailed Western enterprise case of cross-vendor agent-to-agent conversation was found. Critics focus on security, immature identity, version churn, and the gap between "supports" and "uses".

### Cited Findings
- MCP usage evidence: ChatGPT MCP tool calls at 98 times their January 2026 level by August; one provider (Resend) passed "one million calls in a single month"; Railway's daily MCP users grew more than 500% from July to August. — [AAIF blog, 2026-09-01](https://aaif.io/blog/mcp-usage-surged-as-the-protocol-went-stateless)
- A2A usage evidence is thinner: the Linux Foundation's one-year release cites "active production deployments across multiple industries" (supply chain, financial services, insurance, IT operations) without naming a company. — [Linux Foundation press release, 2026-04-09](https://www.linuxfoundation.org/press/a2a-protocol-surpasses-150-organizations-lands-in-major-cloud-platforms-and-sees-enterprise-production-use-in-first-year)
- Most A2A demand so far has come from Asia-Pacific, driven by consumer devices and assistants rather than enterprise deployments. The AAIF executive director calls A2A "early" and expects mainstream adoption "within three years". The article names no specific Western enterprise A2A deployment. — [Diginomica, 2026-09-10](https://diginomica.com/node/31091)
- "'Supported by' is not the same thing as 'deeply used in production by most developers.'" Security and trust are "the biggest unresolved question" (agent identity, scoped authorization, delegation, poisoned artifacts, audit); small teams risk "architecture cosplay". — [Rost Glukhov, 2026 (undated)](https://glukhov.org/ai-systems/comparisons/a2a-protocol-2026-adoption/)
- A2A is "quieter than MCP in developer chatter because it solves a different, later-stage problem"; the author's verdict: "So no, A2A is not dead." — [Credal, 2026-03-06, updated November 2026](https://credal.ai/blog/what-happened-to-a2a-protocol)
- Trust on the open-protocol path is the customer's responsibility. Microsoft tells makers connecting external A2A agents that they must ensure data flows, quality, permissions and "identity and traceability, and human oversight" themselves. — [Microsoft Learn, ms.date 2026-08-26](https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-agent-agent-to-agent)
- "Agents are going to make mistakes. Agents hallucinate. Who is accountable?" … "It cannot be the agent." — Mazin Gilbert, AAIF executive director, in [Diginomica, 2026-09-10](https://diginomica.com/node/31091)
- A2A-specific risks: a remote agent's replies and even its card description can carry instructions aimed at the reading agent ("agent session smuggling", attributed to Palo Alto Networks Unit 42); agent card signing is optional, so an unsigned card cannot be verified. — [Upsy guide, updated 2026-11-02 (secondary)](https://upsy.ai/guides/a2a-protocol)
- An academic comparison of MCP, A2A, Agora and ANP identifies twelve protocol-level risks. — [arXiv 2602.11327, 2026 (search snippet, paper not opened)](https://arxiv.org/html/2602.11327)
- A 2026 preprint argues the interoperability protocols leave governance unaddressed. — [arXiv 2606.31498, "Governance Gaps in Agent Interoperability Protocols", 2026 (search snippet, paper not opened)](https://arxiv.org/pdf/2606.31498)
- Analyst view: "MCP isn't a governance layer"; treating it as a control plane produces "brittle coupling and security blind spots"; researchers found hundreds to over 1,800 MCP servers exposed to the internet. — [Forrester blog, 2025-07-22, OLDER THAN 12 MONTHS](https://www.forrester.com/blogs/mcp-doesnt-stand-for-many-critical-problemsbut-maybe-it-should-for-cisos/)
- Press view: both protocols showed "relative immaturity" despite strong backing. — [The Register, 2025-07-12, OLDER THAN 12 MONTHS](https://www.theregister.com/2025/07/12/ai_agent_protocols_mcp_a2a/)
- Churn: MCP's July 2026 release removed sessions and deprecated three features, with acknowledged "migration cost"; A2A 1.0 renamed operations and states and restructured the agent card. — [MCP blog, 2026-07-28](https://blog.modelcontextprotocol.io/posts/2026-07-28/); [A2A project, "What's new in v1.0"](https://raw.githubusercontent.com/a2aproject/A2A/main/docs/whats-new-v1.md)
- Much of the cross-vendor agent capability Microsoft ships is preview or has functional limits: Foundry A2A targets are text-only without streaming; Copilot Studio's inbound channels are early-release only. — [Microsoft Learn, ms.date 2026-10-28](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/agent-to-agent); [Microsoft Learn, ms.date 2026-09-30](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent)

### Inferences
- The honest answer to "are agents from different vendors really talking to each other?" is: rarely, and mostly inside one vendor's platform or between a platform and a partner agent approved by an administrator. What is common is one assistant calling many tools.
- For ChatGPT, Claude and Grok specifically, cross-vendor "conversation" today means each assistant separately calling the same shared tool server; the assistants do not address each other.
- The risks critics raise are sharper for agent-to-agent than for tool-calling, because the other side's free-text answers are read by a model that can be steered by them.

### Gaps
- A targeted search for a named, verified enterprise case study of agents from several vendors (for example SAP, ServiceNow, Salesforce, Google) conversing in production returned none; secondary blogs repeat the claim without detail.
- No independent survey of production adoption for either protocol was found; the "41% enterprise production adoption" figure for MCP circulating in blogs has no primary source and was excluded.

## 6. For a small custom hub with an HTTP API: which interface gives the widest reach today

### Takeaway
A remote MCP server (Streamable HTTP, OAuth) is the only single interface that ChatGPT, Claude, Grok and Microsoft's Copilot products can all connect to today; it is also where OpenAI is steering custom-GPT builders as GPT Actions retire. An OpenAPI description remains useful as a second door for Microsoft and for plain automation. An A2A endpoint adds reach only into Microsoft, Google and other enterprise platforms, not into ChatGPT, Claude or Grok.

#### What each client expects from that server
- Transport: ChatGPT accepts SSE and streaming HTTP; xAI's API accepts "Streaming HTTP and SSE"; the MCP specification has deprecated HTTP+SSE in favour of Streamable HTTP. — [OpenAI developer docs, retrieved 2026-11-23](https://developers.openai.com/api/docs/guides/developer-mode.md); [xAI docs](https://docs.x.ai/developers/tools/remote-mcp); [MCP changelog 2026-07-28](https://modelcontextprotocol.io/specification/2026-07-28/changelog)
- Reachability: Claude requires a publicly reachable HTTPS server (or allow-listing Anthropic's IP ranges); Grok requires public internet reachability; ChatGPT requires a public HTTPS endpoint or its Secure MCP Tunnel. — [Claude Help Center](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp.md); [xAI docs](https://docs.x.ai/grok/connectors); [OpenAI Help Center](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)
- OAuth: ChatGPT uses static credentials if provided, otherwise CIMD, otherwise DCR. Claude offers its published identity, automatic registration, or a custom client ID/secret. Microsoft 365 Copilot offers OAuth with static registration, OAuth with dynamic registration, Entra SSO, or none, and uses the redirect address `https://teams.microsoft.com/api/platform/v1.0/oAuthRedirect`. xAI's API documents only a static token or headers. — [OpenAI developer docs](https://developers.openai.com/api/docs/guides/developer-mode.md); [Claude Help Center](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp.md); [Microsoft Learn, ms.date 2026-11-16](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/build-mcp-plugins); [xAI docs](https://docs.x.ai/developers/tools/remote-mcp)

- Feature subset: Copilot Studio uses tools and resources only. — [Microsoft Learn, ms.date 2026-11-19](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agent-extend-action-mcp)
- Governance on business plans: on Claude Team/Enterprise, an Owner adds the connector and each user signs in individually, so Claude only accesses what that user can access; on ChatGPT Business only admins/owners publish, and later server changes are not applied until an admin republishes. — [Claude Help Center](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp.md); [OpenAI Help Center](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt)

#### Reach of an OpenAPI description
- ChatGPT: GPT Actions are defined by an OpenAPI schema with None, API key or OAuth authentication, but they live inside custom GPTs, which retire on December 11, 2026; "Custom actions do not transfer automatically when a GPT is migrated to a plugin." — [OpenAI Help Center, "Configuring actions in GPTs", retrieved 2026-11-23](https://help.openai.com/en/articles/9442513-configuring-actions-in-gpts)

#### Reach of an A2A endpoint
- Reaches Copilot Studio (connected agent), Microsoft Foundry (generally available `a2a` tool), Microsoft 365 Copilot (through admin-approved Agent 365 agents) and Gemini Enterprise (preview, v0.3). — [Microsoft Learn, ms.date 2026-08-26](https://learn.microsoft.com/en-us/microsoft-copilot-studio/add-agent-agent-to-agent); [Microsoft Learn, ms.date 2026-10-28](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/agent-to-agent); [MC1478975](https://mc.merill.net/message/MC1478975); [Google Cloud docs](https://docs.cloud.google.com/gemini/enterprise/docs/register-and-manage-an-a2a-agent)

#### Direction of the conversation
- In every product above the assistant is the client and the hub is the server; server-initiated events ("webhooks and channels" so clients do not have to poll) are a roadmap item, not part of the current specification. — [MCP blog, 2026-08-22](https://blog.modelcontextprotocol.io/posts/mcp-roadmap/)
- Microsoft is the exception that offers open inbound doors to its own agents (Copilot Studio MCP/A2A channels in preview; Work IQ over A2A, MCP and REST). — [Microsoft Learn, ms.date 2026-09-30](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent); [Microsoft Community Hub, 2026-04-30](https://techcommunity.microsoft.com/blog/copilot-studio-blog/work-iq-api-public-preview-build-copilot-powered-agents-with-a2a/4516286)

### Inferences
- Ranking by reach for this reader's four vendors: (1) remote MCP server with OAuth reaches all four; (2) OpenAPI reaches Microsoft durably and ChatGPT only until custom GPTs retire; (3) A2A reaches Microsoft only. A hub that already has an HTTP API and an OpenAPI description gets the widest coverage by putting an MCP server in front of the same operations and keeping the OpenAPI description as the second door.
- A reader who relies on a custom GPT with Actions faces a dated migration: after December 11, 2026 (or the workspace's deferred date) the route from ChatGPT to a custom hub is an MCP app/plugin, and writing through it requires a Business, Enterprise or Edu workspace.
- To be accepted everywhere, the MCP server should offer more than one OAuth client-registration style (CIMD for the current specification, dynamic registration for older clients, and a manually issued client ID/secret for Microsoft and for administrators who prefer it), keep a static-token option for API-style callers such as the xAI API, serve Streamable HTTP, label read-only tools, and avoid deprecated features.
- Design for a small number of plainly described tools rather than a wide catalogue: a Copilot Studio field test found that routing by tool description is not guaranteed, and ChatGPT only relies on the first 512 characters of server instructions.
- What MCP will not give the hub: it cannot start a conversation with an assistant, the assistants will not talk to each other through it, and each vendor's approval, plan and admin rules still apply separately. The hub becomes the shared memory and action layer that each assistant consults, which is coordination through a common tool rather than agent-to-agent dialogue.
- A2A is worth adding later only if the hub must be delegated to as a peer agent inside Microsoft (or Google) enterprise platforms; given version fragmentation it would need to serve both 0.3-style and 1.0 cards.
