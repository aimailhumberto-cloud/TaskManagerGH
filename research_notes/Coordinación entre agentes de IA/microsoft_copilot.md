# Microsoft 365 Copilot, Copilot Cowork and Copilot Studio: how they connect to external systems and to other vendors' agents, and what a corporate tenant allows (state as of 2026-11-23)

Conventions used in these notes: every finding carries its source and that source's date (for Microsoft Learn pages the date is the page's `ms.date`; "accessed 2026-11-23" is used where a page shows no calendar date). Status words are used strictly: **announced**, **preview** (includes "Frontier", Microsoft's early-access programme, and "private preview"), **GA** (generally available). "Search summary" marks a claim taken from a search-result summary whose page was not opened in full. "Admin" means a tenant administrator (Global Administrator, AI Administrator, Copilot administrator or Power Platform admin, as stated).

## 1. What exactly is Copilot Cowork (the "Cowork mode") as of November 2026?

### Takeaway
Copilot Cowork is the "do the work" side of Microsoft 365 Copilot (a Chat/Cowork toggle on the Copilot Home tab): a cloud-hosted agentic system, built with Anthropic's Claude Cowork technology and generally available for work accounts since 16 June 2026, that reads the user's Microsoft 365 data with the user's own permissions and then acts (mail, calendar, Teams, Office files, OneNote, Planner), including long-running, scheduled and event-triggered tasks. It needs a Microsoft 365 Copilot licence plus admin-enabled usage-based billing (off by default), and it can reach external tools through plugins (remote MCP servers and connectors) and a local Edge browser, with no documented direct A2A link to other vendors' agents.

- Cloud hosting: files are not stored locally and tasks keep running when the laptop is off. — [Microsoft Copilot Blog, 2026-06-16](https://www.microsoft.com/en-us/copilot/blog/2026/06/16/copilot-cowork-is-now-generally-available/)

### Inferences
- The reader's "Cowork mode" is almost certainly the Chat/Cowork toggle on Copilot Home; having it means their IT department has already placed them in a spending policy that selects Cowork, so every Cowork task they run is metered in Copilot Credits against a budget IT controls.
- Because Claude, GPT and Grok models are selectable inside Cowork, the reader can already use those *models* inside the corporate boundary; that is different from connecting their *external assistants* (a custom GPT with its own instructions, a Claude account with its own projects and memory), which remain outside.
- Cowork's native "inbox" for work arriving from outside is email, Teams messages and connector events; its native "outbox" is email, Teams, files in OneDrive/SharePoint, OneNote and Planner. Those are the surfaces any cross-vendor hand-off has to use unless IT approves a connector.

### Gaps
- No Microsoft source read here documents Cowork calling an external agent over the A2A protocol; the documented outbound routes are plugins (MCP/connectors), the Edge browser and, in private preview, declarative agents.
- None of the plugin lists read names a plugin for ChatGPT, Claude or Grok as *assistants*. I found no reliable source that such plugins exist.
- The status of the "Cowork 1" model announced in June 2026 is unclear; it is not in the November 2026 model list.
- Reports that "Copilot Cowork with Agent 365" is in preview and that "a spend limit will be required for Cowork in the future" come only from secondary Ignite recaps ([Witivio](https://www.witivio.com/en/blog/microsoft-ignite-2026-announcements/), [Windows Forum](https://windowsforum.com/news/copilot-cowork-at-ignite-2026-new-features-availability-and-admin-controls.452916/), search summaries); not confirmed in the Book of News text read.
- Whether Cowork can read or write Microsoft Loop pages or Microsoft To Do is not stated in any page read.
- The default state of the xAI (Grok) setting in a tenant was not verified.

## 2. Extensibility of Microsoft 365 Copilot: every supported way to call external systems (outbound)

### Takeaway
There are two tiers. The self-service tier (Agent Builder and Cowork skills) cannot call external services on its own; calling external systems happens through Cowork plugins, declarative-agent actions (OpenAPI or MCP), Copilot Studio tools (MCP, Power Platform connectors, HTTP, flows, computer use) and Copilot connectors, all of which are subject to admin controls. MCP is the common thread: it is supported in Copilot Studio, in declarative agents, in Cowork plugins and in "federated" Copilot connectors.

### Cited Findings

**Declarative agents and Agent Builder**
- Agent Builder (the simple builder inside Microsoft 365 Copilot) builds declarative agents with instructions, knowledge (SharePoint, Copilot connectors) and skills; "Agent Builder doesn't support authoring actions that integrate external services. To add low-code actions, connectors, or workflows, copy the agent to Microsoft Copilot Studio." Agents built there cannot be used in Teams group or 1:1 chats. — [Microsoft Learn, "Agent Builder overview", ms.date 2026-11-12](https://learn.microsoft.com/en-us/plugins/agent-builder)
- 2026 additions: natural-language agent creation and sharing agents to Teams teams (March), OneDrive folders and up to 50 files as knowledge (May), declarative agent manifest 1.8 with `EmailActions` and `MeetingActions` write capabilities and "worker agent" references (July), manifest 1.9 with `agent_skills` and a `Fabric` capability (October), "Skills in Microsoft 365 Copilot Chat are generally available" (November). — [Microsoft Learn, "What's New for Microsoft 365 Copilot Developers", ms.date 2026-11-13](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new)
- MCP in declarative agents: a developer wraps a remote MCP server as a plugin (an "action") of a declarative agent using the Microsoft 365 Agents Toolkit or "Work IQ Dev Tools"; authentication options are OAuth (static or dynamic registration), Entra SSO or none; tools are discovered dynamically; testing requires "Custom App Upload Enabled" and "Copilot Access Enabled" on the account ("If they don't, check with your organization admin"). The current page carries no preview label. — [Microsoft Learn, "Build a plugin for a declarative agent from an MCP server", ms.date 2026-11-16](https://learn.microsoft.com/en-us/plugins/build-mcp-plugins)
- History: MCP-based declarative agents were announced on the Microsoft 365 developer blog on 15 Dec 2025, a January 2026 third-party post described them as public preview, and "MCP Apps" in Copilot chat were announced 7 April 2026 (search summaries). — [Microsoft 365 Developer Blog, 2025-12-15](https://devblogs.microsoft.com/microsoft365dev/build-declarative-agents-for-microsoft-365-copilot-with-mcp/); [Microsoft 365 Developer Blog, 2026-04-07](https://devblogs.microsoft.com/microsoft365dev/mcp-apps-now-available-in-copilot-chat/)
- "Interactive UI widgets for declarative agents" extend MCP server-based actions using the OpenAI Apps SDK (March 2026). — [Microsoft Learn, "What's New for Microsoft 365 Copilot Developers", ms.date 2026-11-13](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/whats-new)

**Copilot Studio (the full builder)**

The page has no preview label. — [Microsoft Learn, "Extend your agent with Model Context Protocol", ms.date 2026-11-19](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agent-extend-action-mcp)
- MCP in Copilot Studio was declared generally available in a Microsoft Copilot blog post (search summary; the result showed no date, and the post is believed to be from mid-2025, so older than 12 months). — [Microsoft Copilot Blog (search summary, date not shown)](https://www.microsoft.com/en-us/microsoft-copilot/blog/?p=5213)

- "(General availability) Computer use is now generally available, letting your agents automate web and desktop apps" (May 2026); computer-use standalone tools are preview; the "Windows 365 for Agents MCP server" is GA (June 2026). — [Microsoft Learn, "What's new in Copilot Studio", ms.date 2026-11-04](https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new)

**Copilot connectors (formerly Microsoft Graph connectors)**
- Current name: "Microsoft 365 Copilot connectors". Two kinds: **synced** connectors that index external data into Microsoft Graph (tenant configuration by admins, or "self-serve" where the admin enables and each user authenticates) and **federated** connectors that "use a Model Context Protocol (MCP) model to fetch data in real time, without indexing" (admin enables; users authenticate). Over 100 prebuilt connectors (Box, Dropbox, Google Drive, Confluence, Salesforce, ServiceNow, Jira, SAP, Workday, Zendesk…). Federated connectors are described as read-only, with a note that "Write actions will be available starting early October 2026." — [Microsoft Learn, "Copilot connectors overview", ms.date 2026-10-06](https://learn.microsoft.com/en-us/microsoft-365/copilot/connectors/overview)
- Connectors feed Work IQ too, and admin allow/block controls for connectors apply when they are reached through Work IQ APIs. — [Microsoft Learn, "Work IQ overview", ms.date 2026-11-19](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/)

**Cowork plugins** (see section 1): a user can upload their own plugin package from the Customize page for personal use, and a package can bundle skills and external connectors, including remote MCP servers declared in its manifest. — [Microsoft Learn, "Manage plugins for Copilot Cowork", ms.date 2026-11-16](https://learn.microsoft.com/en-us/copilot/cowork/cowork-manage-plugins)

### Inferences
- Among the routes reviewed, the Cowork plugin upload is the only one whose documentation explicitly lets an ordinary user attach a remote MCP server for themselves without an admin step; the others require developer tooling, maker rights or admin configuration.
- For a non-programmer, the practical outbound options are (a) plugins that IT has made available, (b) a Cowork plugin package that someone technical prepares and the user uploads for themselves, and (c) the Edge browser if IT has enabled it. Declarative-agent actions, Copilot Studio tools and Copilot connectors all require either developer tooling or admin configuration.
- Any system that exposes a remote MCP server over HTTPS with OAuth can in principle be attached to Copilot in four places (Cowork plugin, declarative agent action, Copilot Studio tool, federated connector), which makes MCP the most reusable investment for linking Copilot with outside systems.

### Gaps
- No dated Microsoft statement found that MCP plugins for declarative agents are "generally available"; the current Learn page simply omits a preview label. Treat GA as probable but unconfirmed.
- The apparent inconsistency about federated connectors (read-only text alongside a note that write actions start "early October 2026") is in the source page itself; current write support was not verified.

## 3. Multi-agent features: orchestration, A2A, Foundry, Agent Framework, Agent 365, Entra Agent ID, Teams

### Takeaway

## 4. Inbound from outside Microsoft: how an external agent or app reaches Copilot or the work data behind it

### Takeaway
Three Microsoft doors exist (Work IQ API over A2A/MCP/REST, the Microsoft 365 Copilot APIs, and Microsoft Graph), plus vendor-built connectors from Anthropic and OpenAI that read and optionally write Outlook, Teams, SharePoint and OneDrive through Microsoft Graph. Every one of them requires a tenant administrator's consent or enablement at least once; none can be switched on by an ordinary employee.

### Cited Findings

**Work IQ API (A2A, remote MCP server, REST)**
- "Work IQ API endpoints include A2A, a remote MCP server, and a REST API. Usage is independent of Microsoft 365 Copilot licensing and available through usage-based billing." For Copilot-licensed users Work IQ is included in Copilot experiences but "is subject to usage-based billing for custom and third-party agents"; unlicensed users are billed by usage. — [Microsoft Learn, "Work IQ overview", ms.date 2026-11-19](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/)
- GA date 16 June 2026; billed in Copilot Credits with no separate SKU; Tool API calls cost 0.1 Copilot Credits each, Chat and Context API costs are variable; charges also apply "when you use a third-party agent that grounds in your Microsoft 365 data through the Work IQ APIs". — [Microsoft Licensing News, "Work IQ general availability", 2026-06-02](https://www.microsoft.com/en-us/licensing/news/work-iq-general-availability); [Microsoft 365 Developer Blog, 2026-06-02](https://devblogs.microsoft.com/microsoft365dev/work-iq-production-ready-intelligence-for-every-agent/)
- The Work IQ API (with A2A) entered public preview around 30 April 2026 (search summary). — [Microsoft Tech Community, Copilot Studio blog, 2026-04-30](https://techcommunity.microsoft.com/blog/copilot-studio-blog/work-iq-api-public-preview-build-copilot-powered-agents-with-a2a/4516286)

- Admins can also restrict which knowledge sources makers add (local uploads, SharePoint and OneDrive, public websites) from the Power Platform admin center (October 2026). — [Microsoft Learn, "What's new in Copilot Studio", ms.date 2026-11-04](https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new)

**Purview and sensitivity labels for Cowork**
- Supported for Cowork: DSPM for AI, auditing, sensitivity labels, encryption without labels, data loss prevention, Insider Risk Management, Communication Compliance, eDiscovery, Data Lifecycle Management. Not supported: data classification, Compliance Manager. — [Microsoft Learn, "Use Microsoft Purview to manage data security & compliance for Microsoft 365 Copilot Cowork", ms.date 2026-11-09](https://learn.microsoft.com/en-us/purview/ai-copilot-cowork)

Audit events include starting a conversation, adding/removing/sharing a skill or plugin, running a scheduled prompt, starting a browser task and creating a file in OneDrive. — [Microsoft Learn, same page, ms.date 2026-11-09](https://learn.microsoft.com/en-us/purview/ai-copilot-cowork)
- Information Barriers are not supported for plugin and skill sharing: in tenants with IB enabled, affected plugin and skill uploads are blocked. — [Microsoft Learn, "Manage plugins for Copilot Cowork", ms.date 2026-11-16](https://learn.microsoft.com/en-us/copilot/cowork/cowork-manage-plugins)
- Ignite 2026: Purview DLP for Copilot will block Copilot from referencing files with sensitive information even when unlabelled and extend prompt protection to attachments and linked files (preview). — [Microsoft Ignite 2026 Book of News, Nov 2026](https://news.microsoft.com/events/ignite/2026/book-of-news/)

**Controls aimed at third-party AI tools**
- Ignite 2026: Defender runtime protection for local AI agents "covers Claude Code, GitHub Copilot, Claude Desktop, Open Claw, Ollama, and ChatGPT" (GA on Windows with Defender for Endpoint P2); Intune local AI agent governance discovers agents, flags unapproved ones as noncompliant and blocks them from company data (preview); Global Secure Access adds "MCP Firewall" and "Unsanctioned agents" controls (preview). — [Microsoft Ignite 2026 Book of News, Nov 2026](https://news.microsoft.com/events/ignite/2026/book-of-news/)
- Microsoft's warning to admins on non-Microsoft agents and plugins: "Data processed by non-Microsoft services isn't subject to Microsoft agreements." — [Microsoft Learn, "Agent settings in Microsoft 365 admin center", ms.date 2026-09-03](https://learn.microsoft.com/en-us/microsoft-agent-365/admin/agent-settings)

### Inferences
- The scopes that ChatGPT's and Claude's connectors request (tenant-wide file, site and channel reading) are exactly the kind an employee cannot grant personally; when IT has not approved the app, the employee sees a "need admin approval" style failure rather than a working connection.
- The one self-service door to the outside that the documentation leaves open is a privately uploaded Cowork plugin with a remote MCP connector; it is still visible to IT (audit log) and can be blocked, so it should be treated as something to clear with IT rather than a loophole. Sending corporate content through it to a non-approved service may breach company policy even if the product allows it.
- Tooling that IT departments received in 2026 (Agent 365, Defender and Intune agent governance, MCP firewall, Purview DLP for Copilot) is aimed precisely at discovering and restricting unapproved AI agents and MCP servers, so informal bridges are increasingly likely to be noticed.

## 6. Realistic bridges for a business user in a locked-down tenant

### Takeaway
The dependable bridges are the ordinary collaboration surfaces Cowork already reads and writes (email, Teams messages, files in OneDrive or SharePoint, Planner, OneNote), used as a shared "mailbox" between assistants; they need no new permission on the Microsoft side. What decides feasibility is the other side: whether IT has approved the other vendor's Microsoft 365 connector. Protocol bridges (MCP, A2A, Work IQ, webhooks) exist and several are GA, but each needs IT or a developer.

### Cited Findings

**Email**
- Copilot side: Cowork drafts and sends email with approval, and an event-driven task can start "when you receive a matching email"; scheduled prompts can produce a report on a timetable. — [Microsoft Learn, "Use Copilot Cowork", ms.date 2026-11-17](https://learn.microsoft.com/en-us/copilot/cowork/use-cowork)
- Other side: Claude's connector can read Outlook mail and, if an admin enables write tools, send and forward mail (no attachments); ChatGPT has Outlook Email and Calendar apps that depend on Entra admin approval. — [Claude Help Center, accessed 2026-11-23](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector); [OpenAI Help Center (search summary)](https://help.openai.com/en/articles/12143177-outlook-email-and-calendar-apps-in-chatgpt)
- Corporate limit: automatic forwarding to external recipients is governed by the outbound spam policy; since 2021 the default "Automatic - System-controlled" equals "Off - Forwarding is disabled" for new organisations and those not actively using it; blocked forwards bounce with "5.7.520 Access denied, Your organization does not allow external forwarding"; forwarding between internal users is not affected. — [Microsoft Learn, "Control external email forwarding", ms.date 2026-08-18](https://learn.microsoft.com/en-us/defender-office-365/outbound-spam-policies-external-email-forwarding)

**Teams messages**
- Copilot side: Cowork posts to channels and chats with approval and can trigger on channel messages, chat messages or @mentions. — [Microsoft Learn, "Use Copilot Cowork", ms.date 2026-11-17](https://learn.microsoft.com/en-us/copilot/cowork/use-cowork)
- Other side: ChatGPT's Teams app reads chats and channels and can send or reply to messages; Claude's connector reads chats and channels and can send chat messages and post or reply in channels when write tools are enabled; both need Entra admin approval. — [OpenAI Help Center, accessed 2026-11-23](https://help.openai.com/en/articles/12552368-microsoft-teams-connector-for-chatgpt); [Claude Help Center, accessed 2026-11-23](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector)

**Shared files in OneDrive or SharePoint**
- Copilot side: Cowork saves outputs to a OneDrive "Cowork" folder, creates and edits Word, Excel and PowerPoint files in place (version history kept), and reads Markdown and text; OneDrive and SharePoint have native Markdown support (April 2026). — [Microsoft Learn, "Use Copilot Cowork", ms.date 2026-11-17](https://learn.microsoft.com/en-us/copilot/cowork/use-cowork); [Microsoft Learn, "What's new in Copilot Cowork", ms.date 2026-11-16](https://learn.microsoft.com/en-us/copilot/cowork/whats-new)
- Other side: Claude's connector reads Word, Excel, PowerPoint, PDF and plain-text files and can create or update OneDrive and SharePoint files with write tools; ChatGPT's SharePoint app searches .txt, .pdf, .docx, .pptx, .xlsx and .csv and can upload or update files if write actions are enabled. — [Claude Help Center, accessed 2026-11-23](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector); [OpenAI Help Center, accessed 2026-11-23](https://help.openai.com/en/articles/12143177-sharepoint-app-for-chatgpt)

**Planner, OneNote, Loop, To Do**
- Planner: Cowork's Planner Plugin (November 2026; admin must make it available) creates and updates plans and tasks; ChatGPT's Teams app can read, create, update and delete Planner tasks (with `Tasks.Read` / `Tasks.ReadWrite` approved in Entra). — [Microsoft Support, "What is the Planner Plugin?", accessed 2026-11-23](https://support.microsoft.com/planner/planner-plugin-overview); [OpenAI Help Center, accessed 2026-11-23](https://help.openai.com/en/articles/12552368-microsoft-teams-connector-for-chatgpt)
- OneNote: Cowork reads and (when available) edits pages; Claude's connector cannot read OneNote. — [Microsoft Learn, "Use Copilot Cowork", ms.date 2026-11-17](https://learn.microsoft.com/en-us/copilot/cowork/use-cowork); [Claude Help Center, accessed 2026-11-23](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector)

**Power Automate / Copilot Studio workflows and webhooks**
- A Copilot Studio workflow can run Copilot Chat or a Cowork task through a "Copilot node" (preview), agents can run on triggers from connected services (preview on the Microsoft Copilot harness), and flows can call a Copilot Studio agent ("agent node", March 2026). — [Microsoft Learn, "What's new in Copilot Studio", ms.date 2026-11-04](https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new)
- Admins can block the HTTP connector and event triggers for agents, or allow only named endpoints through endpoint filtering. — [Microsoft Learn, "Configure data policies for agents", ms.date 2026-10-01](https://learn.microsoft.com/en-us/microsoft-copilot-studio/admin-data-loss-prevention)

**MCP**
- Out from Copilot: a Cowork plugin with a remote MCP server (user-uploadable for self), a Copilot Studio MCP tool, a declarative-agent MCP action, or a federated Copilot connector (sections 1 and 2). — [Microsoft Learn, "Manage plugins for Copilot Cowork", ms.date 2026-11-16](https://learn.microsoft.com/en-us/copilot/cowork/cowork-manage-plugins)
- In to Copilot: the Work IQ remote MCP server (GA, admin enablement and consent, usage-billed) and a Copilot Studio agent exposed as an MCP server (preview). — [Microsoft Learn, "Work IQ MCP overview", ms.date 2026-11-10](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/mcp/overview); [Microsoft Learn, ms.date 2026-09-30](https://learn.microsoft.com/en-us/microsoft-copilot-studio/agents-experience/publication-channels-mcp-agent-to-agent)

**A2A**
- Out from Copilot: Copilot Studio standard-harness agent to an external A2A agent (GA April 2026); Foundry `a2a` tool (GA). In to Copilot: Work IQ A2A endpoint (GA June 2026, admin consent); Copilot Studio A2A channel (preview, A2A 1.0 clients only). — [Microsoft Learn, "What's new in Copilot Studio", ms.date 2026-11-04](https://learn.microsoft.com/en-us/microsoft-copilot-studio/whats-new); [Microsoft Learn, "Work IQ A2A overview", ms.date 2026-08-20](https://learn.microsoft.com/en-us/microsoft-365/copilot/extensibility/work-iq/a2a/overview); [Microsoft Learn, Foundry A2A, ms.date 2026-10-28](https://learn.microsoft.com/en-us/azure/foundry/agents/how-to/tools/agent-to-agent)

**Browser**
- If IT enables "Cowork Browsing", Cowork can operate websites in Edge with the user's existing sign-ins, subject to the organisation's site blocks and DLP; it hands the tab back for passwords, MFA and CAPTCHAs. — [Microsoft Learn, "Use the local browser with Copilot Cowork", ms.date 2026-10-22](https://learn.microsoft.com/en-us/copilot/cowork/cowork-local-browser)

**Safety properties relevant to assistant-to-assistant loops**
- Event-driven tasks default to draft-and-approve, are rate-limited and are protected against self-triggering loops. — [Microsoft Learn, "Manage Copilot Cowork for your organization", ms.date 2026-11-17](https://learn.microsoft.com/en-us/copilot/cowork/cowork-admin-governance)
- Emails that Claude sends through its connector carry an attribution header, but "Some file writes, calendar writes, and Teams messages aren't tagged as agent-initiated." — [Claude Help Center, accessed 2026-11-23](https://support.claude.com/en/articles/12542951-set-up-the-microsoft-365-connector)

### Inferences
Assessment of each bridge for a business user who is not an admin (judgement based on the cited defaults and requirements; no source quantifies how common each block is):

| Bridge | Copilot/Cowork side | Other assistant's side | Likely status in a locked-down tenant |
| --- | --- | --- | --- |
| Email to self or a shared mailbox | Works today with Cowork (send with approval; trigger on matching email) | Needs the vendor's Outlook connector approved by IT, or the user pastes/forwards manually | Internal email: allowed. Automatic forwarding to an outside address: usually blocked by default. Third-party connector: blocked unless IT approved it |
| Teams channel or chat as hand-off thread | Works today (post; trigger on message or @mention) | ChatGPT Teams app or Claude connector with write tools, both needing Entra admin approval | Allowed on the Copilot side; other side only if the vendor app is sanctioned |
| Hand-off folder in OneDrive/SharePoint (task and result files in .docx or .txt) | Works today (create, edit, read; outputs in the "Cowork" folder) | Same connectors; file formats overlap on .docx, .xlsx, .pptx, .pdf, .txt | Same as above; the most robust option where a connector is approved, and still usable by manual download/upload where it is not |
| Planner board as shared task list | Needs the Planner Plugin made available by the admin | ChatGPT Teams app can read and write Planner tasks; not listed for Claude's connector | Plausible where ChatGPT Enterprise is sanctioned |
| OneNote page | Cowork reads/edits (new, availability varies) | Claude's connector cannot read OneNote | Weak bridge |
| Private Cowork plugin with a remote MCP server | User can upload for self | The other system must offer an MCP server reachable over HTTPS with OAuth or no auth | Technically open by default, visible to and blockable by IT; needs someone technical and should be cleared with IT |
| Power Automate / Copilot Studio workflow with HTTP or triggers | Preview nodes can run a Cowork task | Any system that can call or receive a webhook | Often restricted by data policies (HTTP connector, triggers); needs maker rights |
| Work IQ (MCP or A2A) | GA | Any MCP/A2A client with Entra sign-in | Blocked until a Global Administrator enables Work IQ, grants consent and accepts usage billing |
| Copilot Studio agent calling an external A2A agent | GA (standard harness) | The other agent must expose an A2A endpoint | Builder plus data-policy clearance needed |
| Cowork driving another assistant's website in Edge | Only if IT enabled browser use | The assistant's web app | Fragile and policy-sensitive; off by default |
| Copy and paste by the human | Always possible within company policy | Always possible | The fallback that works everywhere; data-handling rules still apply |

- The pattern that fits a non-technical manager today is "shared surface, human in the loop": Cowork writes a clearly named hand-off file or message and the other assistant reads it (through an approved connector or by the user attaching it), then replies the same way. The approval prompts on Cowork's side keep the user in control of what leaves.
- The first question for the reader's IT department is therefore not about Copilot but about the other vendors: "Is the ChatGPT or Claude Microsoft 365 connector approved in our tenant, and with read-only or write permissions?" The second is whether IT would enable Work IQ for a governed MCP/A2A route, noting that Microsoft says official OpenAI and Anthropic integrations are "coming soon".
- Loop protection and rate limits on Cowork's event-driven tasks mean two assistants answering each other automatically through email or Teams will be throttled; designs should include an explicit "done" marker and a human approval step rather than relying on open-ended ping-pong.
